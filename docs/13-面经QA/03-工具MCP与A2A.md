# 03｜工具、MCP 与 A2A

## Q1：Function Calling、Tool、MCP 分别是什么？

**答：**Function Calling 是模型以结构化参数提出调用请求的接口能力；Tool 是被调用的具体业务动作或查询；MCP 是客户端与外部能力提供方之间标准化发现、连接和调用的互操作协议。MCP 不替代工具治理：调用前仍要做身份、权限、参数校验、超时和审计。

## Q2：MCP 和 A2A 的区别？

**答：**MCP 的中心是“给模型/Agent 接工具、资源和提示能力”；A2A 的中心是“让独立 Agent 之间发现能力、委派任务并交换任务状态”。前者偏能力接入，后者偏跨 Agent 协作。若只是调用一个日历或数据库服务，用 MCP/普通 API 即可；若任务需交给另一个自治系统持续处理、回报进度，再考虑 A2A。

## Q3：怎样设计一个可靠 Tool？

**答：**单一职责、语义明确、参数和返回值都有 JSON Schema；输入做服务端校验，输出使用稳定的错误码与可恢复错误信息。工具要显式声明读写级别、幂等语义、超时、重试策略和副作用。模型不直接拼 SQL 或请求高权 API；高风险操作走策略校验和人工确认。

## Q4：MCP Server 怎么做权限与安全隔离？

**答：**按用户、租户和工具最小权限发放短期凭证，Server 端再次鉴权，不信任模型传来的身份字段；对资源路径、命令参数和网络目标做 allowlist；把第三方工具输出视为不可信数据而非指令。对写操作保留审计日志、审批记录和可撤销/补偿机制。

## Q5：Tool 失败后 Agent 应该怎么做？

**答：**先把失败分类为参数、权限、暂时性、不可恢复和业务冲突。只对可重试且幂等的错误退避重试；参数错误让模型基于结构化报错修正；权限或高风险动作要求用户确认；不可恢复错误停止链路并给替代路径。绝不能把底层异常原样抛给模型后无限重试。
