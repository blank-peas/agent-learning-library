# 05｜多 Agent 与编排

## Q1：何时使用多 Agent，何时不用？

**答：**当子任务可并行、专业能力或权限边界不同、一个上下文窗口无法可靠承载时，多 Agent 才有价值。若任务步骤固定或共享状态极强，单 Agent 加确定性工作流更便宜、更容易测和排错。不能为了“看起来先进”把一个 Agent 拆成多个互相聊天的角色。

## Q2：常见协作模式有哪些？

**答：**主从/调度者—执行者适合中央规划；管道模式适合固定加工链；共享黑板适合多角色读取统一任务状态；辩论/评审模式适合高风险结论的独立验证。无论哪种模式，任务输入、产出 Schema、所有权和终止条件都要明确。

## Q3：多 Agent 如何避免状态竞争？

**答：**把共享状态放在具备版本或乐观锁的结构化存储；每个步骤写入带任务 ID、版本、操作者与幂等键的事件。对于不可并行资源设锁或单一写者；冲突时依据版本、优先级和业务规则合并，而不是让模型自行决定。Checkpoint 用于从最后一致状态恢复。

## Q4：如何设计任务分发与回收？

**答：**调度器先根据能力、成本、时延和权限把工作拆成可验收子任务；Worker 返回结构化结果、证据、置信度和失败类型；调度器只在验收通过后推进状态。应设置队列、超时、取消传播和死信处理，长任务必须能查询进度与恢复。

## Q5：如何评价多 Agent 是否值得？

**答：**与单 Agent/工作流 baseline 对照同一任务集，比较成功率、时延、token 成本、人工介入率和可解释性。还要测协作特有失败：重复工作、状态冲突、循环委派和错误扩散。若效果提升不能抵消复杂度和成本，就回退到更简单的架构。
