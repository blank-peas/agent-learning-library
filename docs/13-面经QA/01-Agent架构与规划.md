# 01｜Agent 架构与规划

## Q1：什么是 Agent？它和工作流、RAG 有什么差别？

**答：**Agent 是“模型决策 + 状态 + 工具执行 + 观察反馈”的受控闭环，适用于路径不确定、需要根据中间结果调整行动的任务。工作流的控制流由开发者预先确定，适合合规、稳定、可预测的流程；RAG 只解决外部知识检索，不负责规划和执行。生产中先判断能否用确定性工作流，只有分支和工具选择确实不可枚举时才引入 Agent。

## Q2：一个生产级 Agent 至少有哪些层？

**答：**业务入口层负责鉴权、限流和任务创建；编排层维护状态机、停止条件和路由；模型层做意图理解与决策；工具层执行受限动作；知识层提供检索证据；最后用安全、评测、trace 横切各层。重点是模型只能“提议”动作，服务端策略层才有“授权执行”的权力。

## Q3：ReAct 和 Plan-and-Execute 怎么选？

**答：**ReAct 每一步根据 Observation 决定下一步，适合探索性任务和外部信息变化快的场景；Plan-and-Execute 先生成可见计划，再按步骤执行，适合结构清晰、可审批、需要进度展示的长任务。常用混合模式：先粗规划，关键节点执行后校验；偏离预期才局部重规划，避免每轮都重新思考。

## Q4：怎样避免 Agent 无限循环？

**答：**不能只设 `max_steps`。我会同时设置步数、token、时长和成本预算；检测相同工具加相同参数的重复调用、连续无进展、反复失败和计划未收敛；命中后返回可解释的中止原因，并转入澄清、降级工作流或人工接管。每次中止要进入 trace，后续作为回归样本。

## Q5：什么时候需要微调而不是继续调 Prompt？

**答：**先确认问题是否来自缺知识、工具能力或输出约束。事实频繁变化优先 RAG；固定格式和少量行为约束优先 schema、few-shot、校验与重试；当高质量、稳定标注数据足够，且任务模式固定、Prompt 已无法稳定改善时，再考虑 SFT 或偏好优化。微调前后必须在冻结评测集上比较收益、成本和回归风险。
