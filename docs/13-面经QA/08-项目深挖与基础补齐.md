# 08｜项目深挖与基础补齐

## Q1：如何讲自己的 Agent 项目？

**答：**按“问题—约束—方案—验证—复盘”讲。先定义用户任务和不能接受的失败，再说明为什么选择 RAG/工具/工作流或 Agent，接着讲关键数据流、权限边界和失败处理，最后给出评测或线上指标，并诚实说明不足和下一步。架构图应能对应实际代码和 trace。

## Q2：面试官问“你实际做了什么”如何回答？

**答：**明确本人负责的模块、接口、关键决策和结果，不把团队成果模糊成“我们做了”。例如：我定义了检索数据 schema、搭建了 rerank 对比集、实现工具审批状态机，并通过某个指标或坏例证明改动有效。被追问时能展示 trade-off 和没有采用方案的原因。

## Q3：Agent 岗为什么还会问后端基础？

**答：**因为模型调用仍要运行在真实服务中。以 Java 岗为例，常见 Redis 缓存一致性与热点过期、MySQL 事务隔离、MQ 的至少一次与幂等、限流、CAP 和服务降级；这些能力决定工具调用、任务队列和状态恢复是否可靠。前端/全栈岗则重点补 BFF、流式连接、鉴权和状态管理。

## Q4：AI Coding 现场题如何准备？

**答：**练习“读仓库—澄清需求—最小修改—测试验证—说明风险”的闭环，不把 AI 生成代码直接提交。要能解释你怎样约束上下文、审查 diff、补边界测试和验证行为；如果模型写错，能定位是需求、上下文、工具还是代码本身的问题。面试时重视验证过程胜过生成速度。

## Q5：如何应对不会的题？

**答：**先说已知边界，不猜术语；把问题拆成目标、约束、可验证的假设和方案选择。比如陌生协议题可以先说明自己会核对其身份、能力发现、状态和安全模型，再说明与 MCP/HTTP/任务队列的对比维度。面试官通常更看重诚实、推理路径和工程判断，而不是背诵。
